libgo

A toolset of small Go libraries by moeghifar: lightweight, fast and clean. Each package under pkg/ stands on its own, so you import only what you use, inside your own framework or directly.

go get github.com/moeghifar/libgo@latest

Requires Go 1.27.3 or later. Current release: v0.3.0.

Philosophy

Standard library first

A third-party dependency must be justified in writing before it is added. go.mod has three direct dependencies for four packages; two of them are stdlib-only.

Lightweight is the product

Binary size, allocation count and cold-start cost are features. Reflection runs at registration time, never in the hot path.

No magic

No global state, no init() side effects, no builder chains. One plain struct literal describes the whole app. Errors are values.

Packages

envy

Environment variables and an optional .env file loaded into a tagged struct. Defaults, required fields, nested structs, slices.

godotenv, optional

climd

Lightweight CLI builder, a Cobra alternative described by one struct. Commands, subcommands, flags, help and version built in.

stdlib only

foreverwork

Typed worker pools and tickers with per-job timeouts, panic recovery and graceful shutdown. No polling, no global state.

stdlib only

xttp

Fiber v3 server with OpenAPI 3.1 generated from your structs, JSON:API errors and hardened production defaults. Handlers stay plain Fiber handlers.

Fiber v3

Planned

xgrpc planned

The gRPC counterpart of xttp: mTLS required, size limits, timeouts, graceful stop, slog access log without payloads, and the same *xttp.Error model mapped to gRPC status codes.

slog extension planned

Small helpers around log/slog for the conventions the other packages already follow: JSON output, request-scoped attributes, no payloads in log lines.

Full service

The getting started page walks through example/, the reference bootstrap: envy loads each command's config, climd parses the command, and serve runs a hardened xttp API that queues jobs on a foreverwork pool.

go run ./example serve
