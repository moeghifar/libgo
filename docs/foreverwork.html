foreverwork

Long-lived worker pools: one pool per job type, each with its own goroutines, queue, per-job timeout and typed handler. No polling: a worker blocks on its channel and wakes the moment a job is queued. Standard library only.

  • One typed pool per job type: Submit takes your struct, a wrong type is a compile error
  • The goroutine count is the concurrency limit; the buffered queue is the backpressure
  • A timeout on every job: zero means a default, never "no deadline"
  • Panic recovery with the stack kept, an OnPanic hook and a *PanicError you can errors.As
  • Graceful shutdown with one budget: in-flight jobs keep a live context, then are cancelled; optional queue drain
  • Cancellation causes (ErrJobTimeout, ErrShutdown) tell the pool's ceiling apart from your dependency's timeout
  • Every: a ticker that cannot overlap itself and survives a panic

What it deliberately does not do: databases, batching, retries, deduplication. A pool is not a durable queue; resumable state belongs in your tables.

Install

go get github.com/moeghifar/libgo/pkg/foreverwork

Quick start

package main

import (
	"context"
	"os/signal"
	"syscall"
	"time"

	"github.com/moeghifar/libgo/pkg/foreverwork"
)

type EmailJob struct{ To string }
type ReportJob struct{ ID int }

func main() {
	ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)
	defer stop()

	wp := foreverwork.New()
	wp.OnResult = func(r foreverwork.Result) {
		// r.Pool, r.Job, r.Duration, r.Err, r.Cause: metrics, slow-job alerts
	}

	email := foreverwork.Register(wp,
		foreverwork.Config{Name: "email", Workers: 4, QueueSize: 100, Timeout: 10 * time.Second},
		func(ctx context.Context, j EmailJob) error { return send(ctx, j) })

	report := foreverwork.Register(wp,
		foreverwork.Config{Name: "report", Workers: 2, QueueSize: 20, Timeout: time.Minute},
		svc.Handle) // a method on your own struct works too
	report.Describe = func(j ReportJob) []any { return []any{"report_id", j.ID} }

	go foreverwork.Every(ctx, foreverwork.EveryConfig{
		Name: "sweep", Interval: 30 * time.Second, Timeout: 20 * time.Second,
	}, sweep)

	done := make(chan struct{})
	go func() { wp.Run(ctx); close(done) }()

	if err := email.Submit(ctx, EmailJob{To: "a@b.c"}); err != nil {
		// ctx.Err() if the caller gave up, foreverwork.ErrStopped if the pool is shutting down
	}

	<-ctx.Done() // SIGTERM
	<-done       // Run returns once in-flight jobs finish, or the grace ran out
}

Register every pool before Run; Register after Run, or a second Run, panics.

FieldMeaningDefault
Logger*slog.Logger for the pool's linesslog.Default()

DisableStackTraceLeave the stack out of the panic log linestack logged

DrainQueueFinish queued jobs on shutdown instead of dropping themfalse

Log lines never include the job payload. Worker[T].Describe adds the fields you choose. Result.Job always carries the whole job.

Shutdown

Cancel the context you gave Run. Then:

  1. Submit returns ErrStopped immediately, including a Submit blocked on a full queue.
  2. Jobs in flight keep an uncancelled context for ShutdownGrace, so a job that is nearly done can write its own outcome.
  3. If the grace runs out, their context is cancelled with cause ErrShutdown. Run returns when they notice.
  4. Queued jobs are dropped, or finished inside the same budget with DrainQueue. Run logs dropped=N.
func handle(ctx context.Context, j Job) error {
	// ...
	if errors.Is(context.Cause(ctx), foreverwork.ErrShutdown) {
		// save partial progress and give up
	}
	return nil
}

wp.OnPanic = func(ctx context.Context, p *foreverwork.PanicError) {
	sentry.CaptureException(p) // p.Stack holds the panicking frames
}

Real usage: a pool behind an HTTP route

From example/serve.go and example/internal/user: the module depends on the pool only through a func, so its test passes a counter instead.

// WelcomeJob is queued for every created user.
type WelcomeJob struct{ Email string }

// SendWelcome handles a WelcomeJob.
func SendWelcome(ctx context.Context, _ WelcomeJob) error {
	slog.InfoContext(ctx, "welcome email sent")
	return nil
}

// serve.go
wp := foreverwork.New()
welcome := foreverwork.Register(wp,
	foreverwork.Config{Name: "welcome", Workers: 2, QueueSize: 10, Timeout: 5 * time.Second},
	user.SendWelcome)
workers := make(chan struct{})
go func() { wp.Run(ctx); close(workers) }()

api := newAPI(cfg)
api.Group("/v1", xttp.BearerTokens(cfg.APITokens...)).Add(user.Routes(welcome.Submit)...)

err := api.Run(ctx, cfg.Addr) // drain the API first, so no request submits to a stopped pool
cancel()
<-workers
